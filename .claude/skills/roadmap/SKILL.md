# Roadmap (계획 문서 기반 실행)

진행 상태의 정본은 [`docs/plans/roadmap.md`](../../../docs/plans/roadmap.md)다. 대화 기억이 아니라 "진행 현황"의 체크 상태와 단계별 "이어서 할 일" 줄을 기준으로 이어 간다.

## 1. 현재 위치

- "진행 현황"의 첫 미완료(`- [ ]`) 단계를 찾고, 같은 문서의 그 단계 절을 읽는다.
- 단계 절에 "결정 필요"가 남아 있으면 코드를 쓰지 말고 AskUserQuestion으로 먼저 묻는다(권고안을 첫 선택지로). 답을 문서에 적는다.
- 작업 트리에 미커밋 변경이 있으면 내용을 보고하고 처리 방법을 묻는다. 사용자 변경을 `git restore`·`checkout`·`stash`로 치우지 않는다.

## 2. 항목 실행

- 코드를 바꾸는 항목은 명세가 있어야 한다. 없으면 spec 스킬로 쓰고 승인받은 뒤 implement 스킬로 구현한다.
- 설정·문서만 바꾸는 항목, Supabase 대시보드처럼 사용자가 직접 해야 하는 항목은 단계 절에 그렇게 적힌 경우만 명세 없이 진행한다. 사용자가 할 일은 절차를 정리해 넘기고 결과를 기다린다.
- 작고 순차적인 작업은 메인 대화에서 한다. 서로 겹치지 않는 큰 구현 묶음만 서브에이전트(`isolation: "worktree"`)에 명세 경로·시나리오 ID·implement 스킬 지시와 함께 맡긴다.

## 3. 기록

- 끝난 항목은 `- [x]`로 바꾸고 단계 절에 `> **결과**` 한두 줄(커밋, 명세, 계획과 다르게 판단한 점)을 남긴다.
- 범위 밖 발견은 "발견 사항" 절에 옮긴다.
- 대화가 길어지면 단계 절의 "이어서 할 일"을 갱신한다(압축·새 대화 대비).

## 4. 보고

- 끝난 항목, 보류 항목과 사유, 다음 실행 대상, 사용자가 직접 해야 할 일.
- `git push`는 Vercel 운영 배포라 사용자가 요청할 때만 한다.
