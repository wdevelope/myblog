## 3. 시나리오

시나리오 하나 = 검증할 수 있는 동작 하나. 제목은 결과를 말한다. 테스트 제목은 `<ID> <한국어 설명>`으로 시작한다(예: `it("CMT-2 다이어리 글에는 댓글을 쓸 수 없다")`). 테스트 하나가 시나리오 여럿을 검증하면 ID를 모두 적는다.

- 새 기능(초안): 정상 흐름, 권한(비로그인·일반 사용자·관리자), 공개 범위(public·private), 타입 라우팅(경로 타입 ≠ 글 타입이면 404), 입력 검증, 없는 대상, 캐시 무효화(revalidateTag·revalidatePath), 클라이언트 상태(로딩·빈 목록·오류).
- 현행: 위 목록 전부가 아니라 권한·공개 범위, 타입 규칙, 부작용(저장·삭제·캐시 무효화), 날짜 경계처럼 깨지면 사고가 나는 동작만 쓴다.

## 7. 미결·확인 필요

- 초안: 승인 전에 사용자가 정할 질문. 승인할 때는 비어 있어야 한다.
- 현행: 역작성 중 발견한 의심 동작·코드와 규칙의 어긋남. 고치려면 별도 작업으로 명세를 고쳐 승인받는다.

## 8. 관련 코드

다른 명세가 코드 경로로 가진 파일 중 이 명세를 구현하는 함수·화면. 없으면 "없음".
